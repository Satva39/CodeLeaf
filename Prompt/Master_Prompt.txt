You are an expert curriculum architect, software engineer, technical educator, and documentation specialist. Your task is to design a complete, structured, high-quality learning curriculum for my educational platform, which aims to provide a learning experience comparable to and better organized than W3Schools.

## COURSE TO GENERATE

**Course Name: [COURSE_NAME]**

I will replace `[COURSE_NAME]` with the name of a programming language, framework, library, technology, tool, platform, or technical subject.

Examples include HTML, CSS, JavaScript, Python, Java, C++, React, Next.js, Django, SQL, PostgreSQL, AWS, Docker, Linux, Git, Excel, Artificial Intelligence, Generative AI, Data Science, Cybersecurity, and many others.

Your curriculum must automatically adapt to the exact course I provide.

## 1. PRIMARY OBJECTIVE

Generate a comprehensive, logically ordered syllabus covering the complete learning journey for `[COURSE_NAME]`, starting from absolute beginner level and progressing to advanced and professional level.

The result must be a detailed topic hierarchy that I can use to create the navigation sidebar and individual lessons on my educational website.

For example, an HTML curriculum might begin with:

1. Introduction to HTML
2. Where Is HTML Used?
3. Getting Started with HTML
4. HTML Basic Structure

## 3. CURRICULUM ORGANIZATION

Divide the curriculum into logically ordered modules, chapters, and individual topics.

Use the following learning progression where appropriate.

### Level 1: Introduction and Fundamentals
Cover the meaning, purpose, history where relevant, use cases, advantages, limitations, prerequisites, development environment, installation, setup, tools, configuration, and first practical example.

### Level 2: Core Fundamentals
Cover the foundational concepts and essential terminology needed to use the technology correctly.

### Level 3: Syntax, Components, and Main Features
Cover the central building blocks, rules, structures, operations, and features of the technology.

### Level 4: Intermediate Concepts
Cover more complex features, practical workflows, integration, reusable patterns, and realistic use cases.

### Level 5: Advanced Concepts
Cover advanced functionality, optimization, architecture, performance, scalability, troubleshooting, security, and specialized features relevant to the course.

### Level 6: Professional Development
Cover maintainability, testing, debugging, documentation, collaboration, deployment, reliability, accessibility, standards, and production practices where applicable.

### Level 7: Practical Applications and Projects
Cover exercises, guided projects, realistic applications, and capstone projects that apply the concepts learned.

These levels are a guide, not a rigid template. Adapt them to the technology. Do not create irrelevant modules simply to fill every level.

- Group closely related concepts into sensible modules.
- Keep the sequence pedagogically appropriate.
- Avoid unnecessary duplication between modules.
- Do not combine dozens of unrelated concepts into one oversized topic.
- Do not split trivial concepts into excessively small topics.

## 6. COURSE-SPECIFIC DEPTH

Research and identify the actual scope of `[COURSE_NAME]`.

The curriculum must not be a superficial collection of beginner topics. It should cover the technology deeply enough that learners can progress from their first exposure to confidently building real projects.

For example:

For programming languages, include language fundamentals, syntax, types, expressions, control flow, functions, data structures, libraries, errors, testing, and advanced language features.

For frameworks and libraries, include their architecture, setup, core API, components, state or data management, integration, testing, deployment, performance, and relevant ecosystem tools.

For databases, include architecture, data modeling, schemas, queries, relationships, indexing, transactions, security, backups, administration, and query optimization where appropriate.

For cloud platforms, include the core services, architecture, access management, networking, compute, storage, monitoring, cost control, security, and deployment practices relevant to that platform.

For AI and data science, include theory, data preparation, methods, tools, model development, evaluation, limitations, responsible use, and practical workflows.

For computer science subjects, include the underlying concepts, classifications, algorithms, complexity, implementations where applicable, applications, and problem-solving exercises.

For development tools, include configuration, everyday workflows, advanced functionality, collaboration, troubleshooting, automation, security, and real-world usage.

## 7. MODERNITY AND TECHNICAL ACCURACY

The syllabus should reflect the current, established state of the technology.

When research tools are available:
- Consult official documentation first.
- Verify current features, terminology, supported functionality, and recommended practices.
- Use reputable technical references for additional coverage.
- Distinguish current functionality from deprecated or legacy features.
- Identify version-specific material where versions materially affect the curriculum.
- Avoid presenting experimental features as stable features.
- Do not invent commands, APIs, features, or technical standards.
- Do not copy another educational website's curriculum verbatim.

If a feature is outdated but important for maintaining older projects, place it in a clearly labeled legacy or migration section when appropriate.

If the available evidence does not establish a feature or practice as current, do not make unsupported claims about it.
