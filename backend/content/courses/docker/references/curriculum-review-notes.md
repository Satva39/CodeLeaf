Lessons use version-adaptive guidance and current docs for Docker Engine/CLI, Compose, BuildKit/Buildx, volumes, network drivers, secrets, security, resource constraints, Swarm, contexts, the Engine API, SBOM and attestations. Do not assume every option behaves identically on Linux, Windows/WSL 2, macOS, or every builder/driver. The course avoids treating `docker-compose` legacy syntax as the default and uses `compose.yaml` / `docker compose` in examples.
- Important correction/clarification: Compose startup order does not by itself prove that a dependency is ready. Health checks, application retries, and explicit readiness behavior need to be discussed and tested. Compose is appropriate for repeatable local and certain single-host deployments; it is not equivalent to multi-node cluster orchestration. Docker tooling builds and distributes OCI-compatible images; Docker Engine should not be stated as a universal runtime requirement for Kubernetes nodes. Swarm is optional and should be exercised only in a designated lab.
- Security and assessment policy: all content remains draft. Docker/Compose commands are illustrative and learner-run only. CodeLeaf currently does not provide a Docker command runner from a lesson page. Exercises use the existing supported server-side text-evidence grader, which does not execute Docker or prove real command results; verification requires local evidence/human review. Protected solution and answer files remain in the backend content repository. No secrets, credentials, production data, XP overrides, or database migrations are added by this course.
- Remaining review before publishing: execute examples on supported Docker Desktop/Engine environments; confirm CLI flags and image tags at publication time; validate Compose files against the target CLI; review all generated lesson explanations, multiple-choice answers, exercise evidence tokens and solution briefs; perform human review of all project artifacts and the security assumptions.
