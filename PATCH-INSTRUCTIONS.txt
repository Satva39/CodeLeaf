CodeLeaf — Implementation and Release Notes
============================================

Project architecture
--------------------
- Frontend: React, JavaScript/JSX, Vite.
- Backend: Python, FastAPI, SQLAlchemy and Alembic.
- Database: PostgreSQL (production hosted by Neon).
- Deployment: Vercel frontend, Render API.

Safe change workflow
--------------------
1. Back up or commit the current working tree before applying source overlays.
2. Keep provider credentials only in local/host environment settings. Never commit .env, tokens, passwords, private keys, database dumps or account exports.
3. Validate course/content manifests before import. Publishing commands write to the configured database; check DATABASE_URL safely before using --apply or --publish.
4. Test backend and frontend changes locally before pushing. Do not equate a unit test with live provider verification.
5. Before production schema changes, create and verify a database backup, review the migration, and record the expected Alembic head.
6. Keep server-executed learner code in a separately isolated runner. Do not run untrusted source in the main API process or on a host with production secrets.

Recommended local verification
------------------------------
From backend/:
    python -m compileall -q app scripts alembic
    python scripts/check_alembic_heads.py
    python scripts/check_release_readiness.py --skip-content-validation

From frontend/:
    node scripts/test_course_catalog_filters.mjs
    node scripts/test_api_client.mjs
    node scripts/test_auth_ui_contract.mjs
    npm run build

For the broader integrated suite, see INSTALL-INSTRUCTIONS.txt in the consolidated patch bundle and docs/REMAINING_WORK_STATUS.md in the repository.

Operational status
------------------
Local isolated tests do not confirm live email delivery, payment-provider behavior, production database restore, public runner isolation, or every responsive browser interaction. Verify these separately before declaring a production release complete.
